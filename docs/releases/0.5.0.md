# Keycloak AI Skills 0.5.0

This version expands the collection from five to ten skills, adding feature implementation, multi-release backports, CI diagnosis, review-feedback corrections and reference maintenance.

## New workflows

- `implement-feature` delivers new Keycloak capabilities and enhancements with acceptance tests and documentation. It checks applicable feature maturity, permissions, compatibility and migration behavior, and preserves the boundaries of mixed feature/fix and review-only requests.
- `backport-pr` adapts one merged PR to one or more requested release branches using separate Git worktrees and the target repository's `.github/scripts/pr-backport.sh`. It preserves commit provenance, handles conflicts and interrupted runs, validates each target, and creates or reuses PRs within the requested publication scope.
- `update-skill` checks existing guidance against authoritative references and applies relevant corrections. It distinguishes target versions, moved sources, unavailable evidence and changes that belong to another release or profile. Plugin installation and upgrades remain separate operations.
- `diagnose-ci` investigates failures at the tested revision and run attempt, separates causal failures from cascades, checks retry and test-isolation evidence, and recommends next actions. It includes a local correction when requested and keeps source conclusions distinct from executed reproduction.
- `address-review` checks feedback against current code and requirements, applies justified corrections, validates the combined change and drafts thread-specific replies. It handles outdated comments, conflicting requests and concurrent head changes while keeping publication and thread resolution within authorization.

## Authoring and documentation

`add-skill` now distinguishes editorial edits, existing workflow changes and new skills before loading supporting resources. Workflow changes use a behavioral baseline and candidate comparison; editorial changes stay scoped to the correction and relevant checks. Evaluation guidance separates per-task measurements from optimization overhead and makes no savings claim from word counts alone. Available Ripwire assistance can help identify relevant implementations, helpers and tests; findings require source verification, and repository search remains the fallback. Source investigation stops when the relevant questions are answered, while required evaluation and validation still apply.

The catalog, client routing, usage examples and package descriptions cover all ten skills. Shared evidence, security and optional Ripwire references are bundled inside their consumer skills. Standalone relocation checks now cover every collection skill. No additional AI plugin is required to use these workflows.

Repository contributors now have a shared `AGENTS.md` entry point for creating, maintaining, updating and validating skills.
Claude imports this guidance through `CLAUDE.md`, Gemini selects it through repository-local settings, and Copilot receives a generated copy checked by the existing synchronization workflow.
Gemini's setup keeps repository maintenance guidance out of installed-extension context, and Bob's installed-extension routing remains in `BOB.md`.
Review and feature skill wording clarifies the expected maintainer judgment while preserving the detailed review criteria.

## Validation and limits

Release preparation includes generated-guidance and package checks, the repository's 49 automated tests, and independent static review. Synchronization coverage includes missing or stale Copilot instructions, read-only checks, refresh behavior and repository containment. Recorded offline evaluations cover authoring, reference maintenance, triage, fixes, PR review, backports, feature implementation, CI diagnosis and review feedback. The backport script was also exercised with real local Git repositories and a simulated GitHub CLI; those checks did not create actual GitHub PRs.

The existing triage, fix and review workflows met their evaluated baseline criteria, so those results do not establish a behavioral improvement. The new feature workflow also met the same criteria as its no-skill baseline. Synthetic scenarios and local simulations do not establish live application correctness or reliability across repeated runs.

Live feature, backport, CI-diagnosis and review-feedback trials, installed-client activation checks and loading the repository guidance in each client remain pending. The release workflow runs the hosted Linux/Windows validation matrix before publication. No live Keycloak feature, backport PR or deployment was performed during skill authoring.

## Upgrade

Update the plugin or extension through your client's existing installation workflow and start a new session. Standalone installations must copy the complete skill directory, including its bundled resources.
